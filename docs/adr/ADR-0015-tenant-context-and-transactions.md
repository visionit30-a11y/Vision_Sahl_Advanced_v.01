# ADR-0015: سياق الجهة وحدّ المعاملة

- **الحالة:** مقبول رسميًا ضمن المجموعة الثالثة عند `e91c30f98ea309b3326c2ee48c7fca9ee8620bb4`؛ Backend ‏153 وFrontend ‏213، وبوابة `03-test.ps1` ‏16 PASS وخروج 0 وشجرة نظيفة عند القبول.
- **التاريخ:** 2026-09-07
- **المرحلة:** Phase 2A — المجموعة المنطقية الثالثة
- **المرجع:** SRS §6، وADR-0014، واعتماد المالك نطاق المجموعة الثالثة بعد قبول المجموعة الثانية.
- **يحل محل:** توصية `SET LOCAL` في قسم «أثره على RLS» من ADR-0005 فقط.

## السياق

لا توجد مصادقة في Phase 2A. تحتاج الخدمة التي تعمل لجهة إلى سياق صريح قبل فتح معاملتها،
ولا يستطيع HTTP إثبات هذا السياق من قيمة يرسلها العميل. اتصالات PostgreSQL يعاد استعمالها،
فلا يجوز إبقاء معرّف جهة على اتصال تستخدمه معاملة لاحقة.

المجموعة الثالثة تؤسس السياق وحدود المعاملة والدالة التي تقرؤه. **سياسات RLS، وجدول الفحص،
ومصفوفة الهجمات، واختبار التجمّع النهائي بحجم اتصال واحد ليست ضمن هذه المجموعة.**
وجود الدالة وحدها لا يعزل الصفوف؛ أُنجز برهان السياسات لاحقًا في Group 4 وفق ADR-0016،
على fixture حقيقية فقط، وقبل المالك تلك المجموعة عند `bf673326`.

## القرار

### 1. سياق صريح والتحويل عند الحد الموثوق

`TenantContext` قيمة جامدة تحمل `TenantId` مطلوبًا، لا سياقًا اختياريًا في خدمة تتطلب جهة.
تتحقق الهوية وقت التشغيل وفق عقد UUIDv7 في ADR-0014. التحويل من UUID الخام يحدث عند حد
خدمة موثوق فقط؛ لا يحوّل التحقق الشكلي قيمة عميل إلى مصدر ثقة. تُمرّر الخدمة السياق صراحةً؛
غيابه أو فساد هويته يرفض العمل قبل فتح جلسة أو إرسال SQL، بلا جهة افتراضية أو سياق منصّة.

### 2. فصل حسم HTTP عن الخدمة والاختبار

| التنفيذ | المصدر | الاستخدام |
|---|---|---|
| `NoTenantResolver` | لا مصدر؛ يرفض دائمًا | افتراضي كل HTTP يحتاج سياق جهة |
| `ExplicitTenantResolver` | قيمة برمجية تتحقق | الخدمة والاختبارات فقط |

`NoTenantResolver` لا يقرأ body أو query أو header أو `X-Tenant-ID` أو subdomain.
طلب السياق منه يفشل بـ`500 internal_error` ضمن عقد الأخطاء القائم، مع حدث
`tenant_context_missing` دون قيمة عميل خام أو بيانات حساسة. نقاط الصحة مستقلة عن السياق.
يحمي اختبار عقد تركيب الـAPI من استيراد أو تسجيل الحسم الصريح. مصدر مصادَق عليه يأتي
لاحقًا بتنفيذ آخر؛ لا Login أو Session أو JWT أو RBAC في هذه المجموعة.

### 3. حد المعاملة يملك دورة حياتها

مدخل العمل `tenant_transaction(context)`، لا جلسة عامة وضبط اختياري للسياق. الترتيب:

1. التحقق من `TenantContext` وهويته قبل فتح الجلسة.
2. فتح جلسة ومعاملة صريحة.
3. ضبط سياق PostgreSQL بمعامل مربوط داخل المعاملة النشطة.
4. تنفيذ عمل الخدمة ضمن الحد.
5. commit عند النجاح أو rollback عند الاستثناء، ثم إغلاق الجلسة.

```sql
SELECT set_config('app.tenant_id', :tenant_id, true)
```

`:tenant_id` معامل مربوط لا تركيب نصي. `true` تحصر الإعداد في المعاملة وتعيده PostgreSQL
إلى حالته السابقة عند نهايتها. يمنع المشروع أي ضبط سابق على مستوى الجلسة، ولذلك تختبر
هذه المجموعة أن القارئ يعيد `NULL` بعد commit وبعد rollback.

**ممنوع:** `SET app.tenant_id`، و`set_config(..., false)`، و`AUTOCOMMIT` لمسار عمل
الجهة، وضبط السياق خارج معاملة، وSQL interpolation. صيغة `SET LOCAL app.tenant_id = ...`
لا تقبل معامل قيمة مربوطًا لهذا الغرض؛ `set_config` توفر ذلك دون تركيب SQL.

يُحذف `get_session()` العام. يعيد الحد واجهة `TenantTransaction` المحدودة إلى
`execute()` و`scalar()` و`scalars()` فقط؛ لا يعيد `AsyncSession` أو نوعًا مشتقًا
منه. لا تكشف الواجهة `commit()` أو `rollback()` أو `begin()` أو `get_transaction()`
أو `connection()` أو `sync_session`، ولا تضيف واجهات ORM لأعمال CRUD تجارية.
حجب `commit()` و`rollback()` على جلسة مكشوفة لا يكفي: يستطيع مستدعيها الوصول إلى
`get_transaction().commit()`؛ لذلك تملك حدود المعاملة الجلسة ومقبض المعاملة كليهما.

تبقى `AsyncSession` الخام ومصنعها خاصين، مع `autobegin=False`
و`close_resets_only=False`. تدير معاملة السياق commit وrollback، ولا يمكن استعمال الجلسة
بعد إغلاق الحد. يُربط `tenant_id` بالسجل داخل الحد ثم يستعاد سياق السجل السابق عند الخروج.

يمنع الحارس إنشاء جلسات أو محركات خام داخل خدمات الجهات وتركيب الـAPI. هذا عقد لمسار
الكود المعتمد، **وليس ضمانًا ضد Python اعتباطي أو SQL مباشر**؛ برهان RLS تحت السياق
المحدد موثق في ADR-0016.
تبقى اتصالات الصحة والمهاجرات واختبارات القاعدة الإدارية متميزة عن خدمات الجهات.
لا توسعة لسياسة المعاملات المتداخلة في هذه المجموعة.

### 4. الدالة تقرأ السياق ولا تمنح الثقة

تُنشأ `app.current_tenant_id()` بمهاجرة مستقلة عكوسة، بلا probe أو سياسة RLS.

| الخاصية | العقد |
|---|---|
| الناتج | `uuid` |
| الاستقرار | `STABLE` |
| الصلاحيات | `SECURITY INVOKER`؛ ليست `SECURITY DEFINER` |
| إعداد غائب أو فارغ | `NULL` |
| نص UUID غير صالح | `NULL`؛ التقاط خطأ تحويل UUID المحدد فقط |
| UUID صالح نحويًا | القيمة نفسها من نوع `uuid` |
| مصادر أخرى | لا lookup ولا fallback ولا default/platform tenant |

**قرار القيمة غير الصالحة هو `NULL`.** لا تنفذ الدالة تفويضًا ولا تبحث عن وجود الجهة.
تحقق UUIDv7 مسؤولية `TenantId` في الخدمة، أما قارئ PostgreSQL فيمرر UUID صالحًا نحويًا
كما ينص عقده. لا يطابق `NULL` جهة في سياسة المقارنة اللاحقة؛ الدالة وحدها لا تمنع الصفوف.

حاجة دور التشغيل هنا `USAGE` لمخطط `app` و`EXECUTE` للدالة فقط. لا `CREATE`
ولا ملكية مخطط أو جدول أو دالة للتطبيق. يبقى `tenants` جدول منصّة وفق ADR-0014.

## التحقق وإجراء الإغلاق

نجح تشغيل الخلفية كاملًا: **153 passed**، منها 88 اختبارًا سابقًا و65 اختبارًا جديدًا:
36 للسياق وHTTP، و7 اختبارات وحدة لحد المعاملة، و14 للدالة، و8 لحد المعاملة على PostgreSQL.
وصلت قاعدة PostgreSQL الفعلية إلى `0003_tenant_context_function` عند head.

تغطي الاختبارات السياق والتحويل والحسم والرفض وحراس الحدود، وعقد الدالة ومنحها،
والقراءة داخل المعاملة و`NULL` بعد commit/rollback على الاتصال نفسه، والتراجع عند الاستثناء.

قُبلت Group 3 عند `e91c30f` ببوابة محلية 16 PASS وخروج 0، كما تسجل حالة القرار.
أُنجز اختبار `pool_size=1` النهائي ومصفوفة RLS في Group 4 المقبولة عند `bf673326`.
وفي تحقق إغلاق Group 5 على `59811ff` نجح المحلي وCI: ‏222 Backend و213 Frontend،
و17 بوابة محلية ناجحة، ودورة المهاجرات حتى `0004_runtime_privilege_boundary`.
السجلات وروابط run في [وثيقة Phase 2A](../phase-2a.md).

## القرارات المكملة وحدود الإغلاق

[ADR-0016](ADR-0016-tenant-rls-enforcement.md) يثبت RLS وFORCE وبرهان العزل وقرار أن
`tenants` خارج tenant RLS. [ADR-0017](ADR-0017-database-role-separation.md) يثبت فصل
الأدوار وحدود المنح محليًا وفي CI. بقي الترقيم المعتمد كما هو. دليل التنفيذ لا يعني
اعتماد Group 5 أو الدمج؛ هذان بيد المالك، ولا يبدأ Phase 2B.
