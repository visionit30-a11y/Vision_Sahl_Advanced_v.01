# ADR-0020: جلسات خادمية في PostgreSQL

- **الحالة:** معتمد للتنفيذ في Phase 2B — Group 1
- **التاريخ:** 2026-09-07
- **المرحلة:** Phase 2B

## القرار

المصادقة الأساسية تستخدم PostgreSQL server-side sessions. لا JWT كجلسة أساسية، ولا Redis
أو ذاكرة عملية API كمصدر حقيقة.

يرسل العميل bearer opaque عشوائيًا من 32 bytes عبر cookie فقط. لا يحمل user أو tenant أو
role أو permission أو وقتًا. تحفظ قاعدة البيانات SHA-256 digest فريدًا فقط، بينما يملك سجل
الجلسة UUIDv7 عامًا منفصلًا لإدارة الجلسات دون كشف bearer أو digest.

## دورة الحياة

| السياسة | القيمة المعتمدة لـPhase 2B |
|---|---:|
| idle timeout | 30 دقيقة |
| absolute timeout | 8 ساعات |
| concurrent sessions | 5 لكل مستخدم |
| last-seen write interval | 60 ثانية كحد أدنى بين الكتابات |
| remember-me | غير موجود |

وقت PostgreSQL هو المرجع لقرارات الانتهاء. لا يمدد `last_seen` المهلة المطلقة، ولا يعيد جلسة
منتهية أو مبطلة. عند بلوغ الحد، يبطل login الناجح الجلسة الأقدم ذريًا وبترتيب حتمي.

تلتقط الجلسة `users.security_version`. رفع النسخة يبطل كل الجلسات السابقة. تستخدم
`revoked_at` وسبب محدود لإبطال جلسة بعينها. تغيير أو reset كلمة المرور وتعليق/أرشفة المستخدم
ترفع النسخة وتمنع إصدار جلسة اعتمادًا على تحقق قديم.

## الدوران والتبديل

يدور bearer وCSRF token عند login وإعادة المصادقة واختيار/تبديل العضوية. لا دوران دوري أو
لكل request في Phase 2B. لا grace للرمز القديم؛ نجاح واحد فقط عند الدوران المتزامن، والاستجابة
الخاسرة لا تعيد cookie قديمة.

تخزن الجلسة `selected_membership_id` ونسختها دون `tenant_id` مكرر. FK مركب يثبت أن العضوية
تخص مستخدم الجلسة. الاختيار ليس إثباتًا وحده؛ يعاد التحقق من العضوية والجهة عند إنشاء السياق.

يرسل العميل في العمل tenant-scoped معرف العضوية المتوقع لقيد اتساق التبويبات. اختلافه عن
اختيار الجلسة يعيد `tenant_context_changed` قبل العمل، ولا يغير الجهة تلقائيًا.

## الإبطال والطلبات الجارية

Logout يبطل الحالية ويحذف cookie. يمكن للمستخدم إبطال جلسة يملكها أو جميع جلساته؛ IDOR
يمنع بإثبات الملكية. الطلب الذي اجتاز التحقق قبل commit الإبطال قد يكمل عمله القصير، وكل
تحقق يبدأ بعد commit يرفض. لا يدعي النظام إلغاء SQL جارٍ بالفعل.

## Metadata والاحتفاظ

لا ربط أمني صارم بالـIP. يسمح بوصف User-Agent خشن محدود، وIP HMAC بمفتاح purpose-specific
و`key_id` دون IP خام. تزال الجلسات بعد 30 يومًا من الانتهاء أو الإبطال بواسطة صيانة خارج
HTTP؛ لا يمنح runtime DELETE عامًا لهذا الغرض.

## MFA readiness

تحمل الجلسة `authenticated_at` وطرق المصادقة ومستوى assurance الفعلي. كلمة المرور وحدها
لا تسمى AAL2. لا `mfa_secret` أو rollout لـMFA في Phase 2B؛ تخزين عوامل مستقبلية يكون في
نموذج منفصل عند اعتمادها.
