# ADR-0007: بنية نظام التصميم — رموز دلالية + CSS Modules

- **الحالة:** معتمد
- **التاريخ:** 2026-09-05

## السياق

الوثيقتان تمنعان Tailwind وBootstrap وأي إطار CSS بديل، وتوجبان نظام تصميم موحدًا قابلًا
لإعادة الاستخدام، وواجهة ثنائية اللغة بـRTL/LTR من أول Commit، دون تجريد مبالغ فيه.

## القرار

1. **ثلاث طبقات فقط:** لوحة مرشّحة تعرّف رموزًا **دلالية** (`--color-surface`,
   `--color-brand`, `--space-4` …) ← ثم **CSS Modules** لكل مكوّن لا تحتوي قيمة لونية صريحة.
   لا طبقة رابعة ولا نظام أدوات مساعدة.
2. **الخصائص المنطقية إلزامية** (`margin-inline-start`, `inset-inline-start`, `text-align: start`).
   ورقة أنماط واحدة تخدم الاتجاهين بلا مكتبة قلب وبلا نسخة ثانية من CSS.
3. **الأيقونات** SVG بأسلوب خطي موحد تُلوَّن عبر `currentColor` من الرموز الدلالية،
   فتتبع الموديول والحالة والسياق دون رسوم متعددة الألوان تسبب ضجيجًا.
4. **حارس آلي لكل قاعدة** بدل الاعتماد على الانضباط: نص ثابت، تطابق الترجمات، CSS فيزيائي،
   قيمة لونية صريحة، نقاط كسر غير معتمدة، وحدود الاستيراد.
5. **مدخل واحد للمكتبة** (`design-system/index.ts`). الشاشات لا تصل إلى ملفات المكونات.

## ما رُفض عمدًا

- CSS-in-JS: تكلفة وقت تشغيل بلا مقابل هنا.
- مكتبة مكونات جاهزة: تفرض هوية بصرية وتخالف عقد نظام التصميم.
- مولّد رموز متعدد المستويات: يجعل تعديل مكوّن بسيط يمر بطبقات لا داعي لها.
