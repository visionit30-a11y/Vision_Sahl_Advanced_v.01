# ADR-0002: بنية المستودع وحدود الموديولات

- **الحالة:** معتمد
- **التاريخ:** 2026-09-05

## السياق

SRS §4 يحدد المسارات المنطقية (`apps/web`, `apps/api`, `modules/<domain>`, `packages/shared`,
`infra/terraform`, `migrations`, `docs`, `tests`) دون تحديد ما إذا كان `modules/` في الجذر أم
داخل الخلفية، ودون تحديد موضع أداة المهاجرات.

## القرار

1. **`apps/api/app/modules/<domain>/`** هو موضع موديولات المجال — حزمة Python واحدة داخل
   الـ Modular Monolith. هذا يحفظ حدود الموديولات بقواعد استيراد قابلة للفحص الآلي، ويتجنب
   تعقيد التغليف الذي تفرضه الحزم المستقلة، دون أي مساس بمبدأ Modular Monolith.
2. **`migrations/`** يبقى في جذر المستودع كما نص SRS، ويشير إليه `apps/api/alembic.ini`
   عبر `script_location = ../../migrations`.
3. **`packages/shared`** لا يُنشأ في Phase 0 لعدم وجود كود مشترك حقيقي بين الواجهة والخلفية
   بعد؛ يُنشأ عند أول حاجة فعلية (مبدأ عدم التجريد المبكر).
4. **`tests/`** في الجذر مخصص لاختبارات التكامل وE2E العابرة للطبقات لاحقًا. اختبارات وحدة
   الخلفية في `apps/api/tests/` واختبارات الواجهة بجوار مصادرها.
5. **`infra/terraform/`** يُنشأ كهيكل موثق فقط؛ محتواه الفعلي في Phase 11.

## التبعات

- الانتقال لاحقًا إلى حزم مستقلة (إن لزم) ممكن دون تغيير حدود المجال.
- لا قرار في Phase 0 يمنع تطبيق RLS أو Tenancy في Phase 2.
