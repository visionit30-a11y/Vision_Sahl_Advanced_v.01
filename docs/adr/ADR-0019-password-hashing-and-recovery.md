# ADR-0019: تجزئة كلمات المرور وأساس الاستعادة

- **الحالة:** معتمد للتنفيذ في Phase 2B — Group 1
- **التاريخ:** 2026-09-07
- **المرحلة:** Phase 2B

## القرار

يخزن `auth.password_credentials` اعتماد كلمة المرور منفصلًا عن بيانات المستخدم. المخزن الوحيد
هو PHC string لـArgon2id؛ لا plaintext ولا تشفير قابل للعكس ولا تاريخ كلمات مرور في Phase 2B.

المعاملات الابتدائية الصريحة:

| المعامل | القيمة |
|---|---:|
| memory | 65536 KiB |
| time | 3 |
| parallelism | 4 |
| salt | 16 bytes |
| hash | 32 bytes |

تضاف `argon2-cffi` كتبعية مباشرة عند Group 3، ويثبت الإصدار في `uv.lock` دون تحديث غير لازم
لباقي الشجرة. المعاملات نقطة بدء تحتاج benchmark حاجزًا على Windows وCI قبل قبول Group 3.
لا تخفض تلقائيًا عند الضغط.

تنفذ عمليات Argon2 خارج event loop، بعدد عمال محدود وبدون معاملة PostgreSQL مفتوحة. بعد
نجاح التحقق فقط يستخدم `check_needs_rehash`. تحديث rehash مشروط بالـhash ونسخة credential
القديمين كي لا يعيد كلمة مرور تجاوزها تغيير متزامن.

## سياسة كلمة المرور

- 15 إلى 128 Unicode code points للمصادقة بكلمة مرور واحدة.
- Unicode NFC في الإنشاء والتغيير والتحقق، دون تغيير حالة الأحرف أو قص أو حذف مسافات.
- السماح بالمسافات واللصق ومديري كلمات المرور.
- لا قواعد تركيب ولا تغيير دوري بلا حادث أو سبب.
- قائمة محلية معتمدة للكلمات الشائعة والمخترقة؛ يثبت مصدرها وترخيصها وتحديثها قبل gate.
- لا password أو hash في API أو logs أو exceptions أو repr أو fixtures حقيقية.

اسم الدخول في Phase 2B هو بريد عالمي فريد. تحفظ نسخة عرض ونسخة معيارية للمقارنة. النسخة
الأولى تقبل ASCII email، تزيل المسافات الخارجية وتطبع الحالة وفق عقد واحد، ولا تطبق قواعد
مزودي البريد مثل إزالة النقاط أو `+alias`. تغيير البريد والتسجيل الذاتي خارج النطاق.

## الاستعادة

- reset token عشوائي 32 bytes، وتخزن SHA-256 digest فقط.
- صالح 15 دقيقة، وأحادي الاستخدام.
- يوجد رمز واحد غير مستهلك وغير مبطل لكل مستخدم؛ الإصدار الجديد يبطل السابق تحت قفل.
- نجاح التأكيد يستهلك الرمز، يغير credential، يرفع user security version، ويبطل كل الجلسات
  والرموز الأخرى في معاملة واحدة. لا auto-login.
- lifecycle منفصل عن delivery. تبقى API العامة معطلة وتعيد `recovery_unavailable` بصورة
  موحدة حتى اعتماد قناة بريد فعلية. لا يعاد الرمز من API أو CLI أو log.
- لا token في query string. تصميم delivery المستقبلي يستخدم صفحة no-store/no-referrer
  تتلقى الرمز بطريقة تمنع حفظه كquery وتزيله قبل الموارد الخارجية.

## مقاومة enumeration والتزامن

الحساب غير الموجود أو المعلق أو كلمة المرور الخاطئة تسلك response عامة واحدة، ويجري dummy
Argon2 verification بالملف الحالي بدل الخروج المبكر. لا ندعي timing متساويًا رياضيًا؛ تثبت
الاختبارات غياب الفروع الكاشفة، والقياس الإحصائي يكون منفصلًا عن assertions زمنية هشة.

تثبت اختبارات اتصالين أن reset token ينجح مرة واحدة، وأن login تحقق من hash قديم لا يصدر
جلسة بعد reset، وأن rehash لا يعيد hash قديمًا فوق password change.
