# ADR-0003: تأجيل التحقق التشغيلي من Redis مع بقائه التقنية المعتمدة

- **الحالة:** معتمد
- **التاريخ:** 2026-09-05
- **القرار من:** مالك المشروع

## السياق

Redis تقنية مقفلة في BRD §8 وSRS TS-05. بوابة خروج Phase 0 في SRS تشترط تشغيل Redis محليًا.
لكن جهاز التطوير (Windows) لا يحتوي Docker Desktop، ولا توجد نسخة ويندوز رسمية من Redis.

## الخيارات التي نُظر فيها

1. إدخال بديل متوافق مع Redis على ويندوز — **مرفوض**: إدخال تقنية إضافية غير واردة في العقد.
2. تثبيت Docker Desktop الآن — **مؤجل**: تغيير كبير على بيئة الجهاز لا تبرره Phase 0 وحدها.
3. تنفيذ Redis كإعداد ومعمارية في Phase 0 وتأجيل التشغيل الفعلي — **المعتمد**.

## القرار

1. **Redis تبقى التقنية المعتمدة دون بديل**، ولا تُستبدل بتنفيذ In-Memory داخل منطق المشروع.
2. في Phase 0 يُنفَّذ: طبقة `app/cache` (مزوّد اتصال)، الإعداد من متغيرات البيئة،
   ونقطة `/health/redis`.
3. `REDIS_ENABLED=false` هي الحالة الافتراضية محليًا في هذه المرحلة؛ وعندها تُبلِّغ نقطة الفحص
   عن الحالة `disabled` صراحة بدل ادعاء النجاح.
4. **بوابة خروج Phase 0 عُدِّلت**: عدم تشغيل Redis محليًا لا يمنع إغلاق المرحلة ما دامت
   المعمارية والإعدادات والاختبارات الممكنة صحيحة.
5. **قبل أي مرحلة تصبح فيها Redis ضرورة وظيفية فعلية** (Phase 3 — المهام الخلفية والإشعارات)
   يجب تشغيل Redis حقيقي والتحقق منه، ولا تُغلق تلك المرحلة بدونه.

## الدين التقني المسجل

| البند | الاستحقاق |
|---|---|
| تشغيل Redis حقيقي والتحقق من `/health/redis` بحالة `up` | قبل إغلاق Phase 3 |
