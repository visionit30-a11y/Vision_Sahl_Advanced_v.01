# ADR-0010: محرك تخصيص الواجهة

- **الحالة:** معتمد
- **التاريخ:** 2026-09-05
- **القرار من:** مالك المشروع (اعتماد خطة Phase 1B-1)

## السياق

المنصة متعددة الجمعيات. كل جمعية قد تريد هوية بصرية تخصها، والمنصة تحتاج افتراضًا يسري على
من لم يخصّص. الحل الساذج — شرط داخل كل مكوّن أو ورقة أنماط لكل جمعية — يجعل إضافة هوية
سادسة تعديلًا في عشرات الملفات، ويجعل كسر التوريث مسألة وقت.

## القرار

### 1. لا مكوّن يعرف اسم هوية

المكوّن يقرأ رمزًا دلاليًا (`var(--color-brand)`) ولا يذكر `teal-calm` ولا أي معرّف آخر.
المحرك يكتب الاختيار المحسوم على `<html>` سمةً واحدة:

```html
<html lang="ar" dir="rtl" data-theme="teal-calm">
```

وملف الهوية يعرّف قيم الرموز تحت `[data-theme='<id>']`. تغيير السمة يعيد الطلاء فورًا: بلا
Build، وبلا إعادة تشغيل، وبلا إعادة رسم React لأي مكوّن.

### 2. الهوية ألوان فقط

ملف الهوية لا يعرّف إلا `--color-*`. المسافات والأحجام والزوايا والظلال ونقاط الاستجابة
والحركة تبقى في `styles/tokens/` مشتركة بين كل الهويات. حارس آلي يرفض أي إعلان آخر داخل
ملف هوية، فيصير الادعاء التالي **بنية لا وعدًا**: تبديل الهوية لا يستطيع إحداث Layout Shift
ولا كسر RTL/LTR — لا يملك ما يزيحه ولا ما يعكسه.

### 3. الحسم دالة نقية بأربع طبقات

`User → Tenant → Platform → Built-in`

`resolveUiSettings` دالة بلا حالة ولا تخزين ولا DOM، تعيد الإعدادات المحسومة **وخريطة
`origin`** تبيّن لكل مفتاح من أي طبقة جاء. `origin` ليست زينة: هي ما يجعل مدير الجمعية يرى
ما ورثه من المنصة وما خصّصه فعلًا.

مستوى المستخدم **مقبول في العقد ولا يُنفَّذ في 1B-1**: إضافته لاحقًا تمرير طبقة إضافية لا
إعادة بناء.

### 4. التخزين خلف واجهة غير متزامنة

`UiSettingsSource` غير متزامنة **من اليوم** رغم أن تنفيذ 1B-1 يقرأ من تخزين المتصفح
متزامنًا، لأن تنفيذ Phase 2 نداء HTTP، وتحويل واجهة متزامنة إلى غير متزامنة لاحقًا يمس كل
مستدعٍ.

**تنفيذ المتصفح مؤقت صراحة.** لا مكوّن يلمس `localStorage` مباشرة — حارس آلي يمنع ذلك خارج
`ui-customization/adapters` وطبقة اللغة. وفشل التخزين لا يكسر التطبيق: الإعداد يُطبَّق
للجلسة الحالية.

### 5. الصلاحيات نقطة وصل لا ضابط أمان

`UiPermissions` واجهة مجردة تسألها الواجهة، فلا اسم دور ولا تحقق صلاحية داخل أي مكوّن.

> **تنفيذ 1B-1 يمنح الصلاحيتين للجميع، لأنه لا توجد هوية مستخدم بعد.** هذه **Seam معمارية
> وليست حماية**. الضبط الحقيقي يأتي مع RBAC في Phase 2 باستبدال التنفيذ وحده.

### 6. سجل بدل الشروط

`themeRegistry` بيانات وصفية فقط: معرّف ومفتاحا ترجمة. القيم في CSS. إضافة هوية سادسة =
ملف CSS + سطر في السجل + مفتاحا ترجمة. لا تعديل في أي مكوّن.

### 7. WCAG AA حارسًا آليًا

اختبار في بيئة node يقرأ ملفات الهويات الخمس، يستخرج قيم الرموز، ويحسب نسبة التباين وفق
WCAG بلا مكتبة إضافية: **4.5** للنص و**3** لغير النص. هوية تفشل لا تُدمج.

## البدائل المرفوضة

| البديل | سبب الرفض |
|---|---|
| ورقة أنماط لكل جمعية | تكرار ضخم، وانحراف مؤكد بين النسخ، وبناء لكل تغيير |
| تمرير الألوان عبر React Context إلى المكونات | كل تبديل هوية إعادة رسم كاملة، وكل مكوّن يصير مسؤولًا عن الألوان |
| CSS-in-JS | يخالف قرار CSS Modules + Design Tokens المقفل |
| كتابة الألوان في السجل بدل CSS | يخرج القيم من طبقة الأنماط ويمنع الطلاء الفوري |

## النتائج

- **إيجابية:** إضافة هوية رخيصة · التبديل فوري · التوريث مرئي · الانتقال إلى تخزين حقيقي
  يمس ملفًا واحدًا · الحُرّاس يمنعون الانحراف بدل الاعتماد على الانضباط.
- **الكلفة:** طبقة تجريد قبل وجود مستخدمين أو جمعيات حقيقية. مقبولة لأن العقد هو ما يمنع
  إعادة الكتابة في Phase 2.
- **`preview-tenant` معرّف معاينة فقط**، ليس جمعية حقيقية ولا Tenant حقيقي، ويزول مع وصول
  Tenancy في Phase 2.
