# خط أساس البيئة والانحرافات المسجَّلة

يوثق هذا الملف الفارق بين **خط الأساس المعتمد** للمشروع و**ما هو مثبت فعليًا** على جهاز
التطوير. الانحراف يُسجَّل ولا يُغيَّر خط الأساس تلقائيًا؛ أي تغيير في خط الأساس قرار من مالك
المشروع.

## 1. المنصات

| المكوّن | خط الأساس المعتمد | المثبت على جهاز التطوير | الحالة |
|---|---|---|---|
| Python | 3.12+ (‏CI يعمل على 3.12) | **3.13.1** (‏`py -3.13`) | ✅ ضمن النطاق المعتمد `>=3.12` |
| Node.js | **20 LTS** (‏CI يعمل على 20) | **24.14.1** | ⚠️ انحراف مسجَّل — راجع أدناه |
| npm | تابع لـ Node | 11.11.0 | تابع |
| PostgreSQL | 16+ | **17** (خدمة `postgresql-x64-17`، منفذ 5433) | ✅ |
| Redis | 7 | غير مشغَّل محليًا | مؤجل بقرار — ADR-0003 |
| Docker | مطلوب في Phase 11 | غير مثبت | مقبول في هذه المرحلة |

### انحراف Node.js — لم يُغيَّر خط الأساس

جهاز التطوير يشغّل **Node 24.14.1** بينما خط الأساس المعتمد **Node 20 LTS**، وملف
`.github/workflows/ci.yml` ما زال يبني على Node 20.

- **الأثر:** البناء المحلي والبناء في CI يعملان على إصدارين مختلفين، وهو مصدر محتمل لفروق
  لا تظهر إلا في أحد الجانبين.
- **لم أغيّر خط الأساس** ولم أعدّل CI.
- **القرار المطلوب لاحقًا (قبل إغلاق Phase 1):** إما رفع خط الأساس وCI إلى Node 24،
  أو تثبيت Node 20 محليًا عبر مدير إصدارات. لا حاجة لحسمه في Phase 0.

## 2. دين تقني مسجَّل

| البند | التفصيل | الاستحقاق المقترح |
|---|---|---|
| ESLint خارج الدعم | `npm install` حذّر: `eslint@9.39.5: This version is no longer supported`. الأداة تعمل بشكل سليم، والتحذير يخص دورة دعم الإصدار لا ثغرة أمنية، ولا يمس كود المنتج. | ترقية إلى الإصدار الرئيسي المدعوم مع بدء **Phase 1** حين يُدخل نظام التصميم قواعد Lint إضافية — لا داعي لتغيير متغيرين في وقت واحد أثناء إغلاق Phase 0 |
| `whatwg-encoding` مهجورة | تبعية غير مباشرة من `jsdom` (بيئة اختبار الواجهة فقط) | لا إجراء — تُحل بترقية `jsdom` لاحقًا |
| تشغيل Redis الفعلي | غير مشغَّل محليًا | قبل إغلاق **Phase 3** — ADR-0003 |
| `C:\Program Files\PostgreSQL\15\data` | مجلد بيانات يتيم من تثبيت سابق أُزيلت ثنائياته | **لا يُلمس ولا يُحذف** — ليس ملكًا لهذا المشروع |
